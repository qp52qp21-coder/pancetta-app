# 熟成タイミング通知 設計書

作成日: 2026-09-02
対象: パンチェッタ熟成手帳（https://github.com/qp52qp21-coder/pancetta-app）

## 目的

塩漬け期間の終了（スパイス工程の開始）と、熟成期間の終了（完成）のタイミングを、
アプリを開いていなくてもスマートフォンで気づけるようにする。

## 前提と制約

本アプリは GitHub Pages 上の静的サイトであり、サーバーを持たない。
本物のプッシュ通知（Web Push）は「時刻になったら通知を送るサーバー」を必須とするため、
現在の構成のままでは実装できない。

追加費用・追加アカウントなしという条件のもと、以下の方針を採る。

| 方式 | 採否 | 理由 |
|---|---|---|
| 端末カレンダーへの予定登録 | **採用** | Android 標準の Google カレンダーが確実に通知する。費用ゼロ |
| Periodic Background Sync による自前通知 | 不採用 | Chrome の裁量で発火せず、通知が来ない事故が起きる |
| アプリ起動時の強調表示 | **採用（補助）** | 通知の見落とし・カレンダー未登録に対する保険 |

利用端末は Android（Google Pixel）を主とする。

## 機能1: カレンダーへの通知登録

### 概要

熟成中の仕込みごとに、Google カレンダーの「予定作成」画面を内容入力済みで開くリンクを提供する。
利用者は「保存」を押すだけで登録が完了し、以後はカレンダーアプリが通知を出す。

### 登録される2件の予定

日付は既存ロジックに合わせ、仕込み当日を 0 日目として数える。

| 予定 | 日付 | 時刻 | 件名 |
|---|---|---|---|
| スパイス工程の開始 | `startDate + d1` 日 | 05:00–05:15 | `🥓 {仕込み名}：スパイスをまぶす日` |
| 熟成完了 | `startDate + d1 + d2` 日 | 05:00–05:15 | `🥓 {仕込み名}：熟成完了・味見の日` |

予定の説明欄には、配合・仕込み開始日・スパイスメモを入れる。

```
パンチェッタ熟成手帳より
配合：塩3% / 砂糖1%
仕込み開始：2026/09/02
スパイス：黒コショウ＋チリパウダー
```

### URL 仕様

Google カレンダーのテンプレート URL を用いる。タイムゾーンは明示する。

```
https://calendar.google.com/calendar/render
  ?action=TEMPLATE
  &text=<件名>
  &dates=YYYYMMDDT050000/YYYYMMDDT051500
  &details=<説明>
  &ctz=Asia/Tokyo
```

各パラメータは `encodeURIComponent` でエスケープする。
リンクは `<a target="_blank" rel="noopener">` として描画する
（`window.open` はポップアップブロックの対象になり得るため）。

### 既知の制限

- **通知の実際の時刻は Google カレンダー側の既定設定に従う。**
  既定が「30分前」の場合、05:00 の予定は 04:30 に鳴る。
  テンプレート URL では通知時刻を指定できないため、
  厳密に 05:00 に鳴らしたい場合は利用者がカレンダー側で「0分前」に変更する。
  この旨をモーダル内に注意書きとして表示する。
- 日数（d1 / d2）を後から変更する機能は現状存在しないため、予定の自動更新は不要。
- 仕込みを削除してもカレンダーの予定は残る。手動削除が必要である旨は表示しない（過剰なため）。

### UI

仕込みカードのボタン行の下に、2行目として横幅いっぱいのボタンを置く。

```
[重量を記録] [完成にする] [削除]
[🔔 通知をカレンダーに登録]
```

押すとモーダルが開く。

```
🔔 通知をカレンダーに登録
チリパウダー入り 2本目

下のボタンを押すとGoogleカレンダーが開きます。
内容は入力済みなので「保存」を押すだけです。

[ 9/9(火) 5:00  スパイスをまぶす日 ]
[ 9/16(火) 5:00 熟成完了・味見の日 ]

※通知が鳴る時刻はGoogleカレンダーの設定に従います
　（既定では予定の30分前）
```

ボタン上の日付表記は `9/9(火)` の形式とし、曜日を含める（何曜日かが即座に分かるため）。
既存の `fmt()` は曜日を持たないため、曜日つきの整形関数を別に用意する。

一度でもどちらかのリンクを押したら（`<a>` の `onclick` で検知）、batch に `calReg: true` を記録し、
カード上のボタン表記を `🔔 通知は登録済み` に変える（再登録のため押下は可能なまま）。

新規仕込みの登録直後は、このモーダルを自動で開く。
登録意図が最も高い瞬間であり、設定漏れを防げるため。閉じるのは自由。

## 機能2: 起動時のお知らせカード

「熟成中」タブの最上部に、条件に合致したときだけカードを表示する。

| 条件（`day` = 経過日数, `total` = d1+d2） | 表示 |
|---|---|
| `day === d1` | 今日からスパイス工程です。スパイスをまぶしましょう |
| `day === total` | 今日が完成予定日です。味見してみましょう |
| `day > total` | 熟成期間が {n} 日過ぎています。味見してみましょう |
| 上記以外 | 何も表示しない |

- 複数の仕込みが該当する場合は、仕込み名つきで複数行を並べる
- 該当なしのときはカード自体を描画しない（画面を圧迫しないため）
- 閉じるボタンは付けない。状態が変われば自然に消える

## データ構造の変更

`batch` オブジェクトに 1 項目だけ追加する。

```js
calReg  // boolean。カレンダー登録リンクを押したことがあるか。既定 false
```

既存データにこの項目は無いが、`undefined` は falsy のためそのまま動作する。
マイグレーション処理は不要。

## 設計ルールの遵守

`CLAUDE.md` に定めた既存ルールをすべて守る。

- 配色は 3 色のみ（お知らせカードはローズ `#B14A5A` をアクセントに使う）
- `alert()` / `confirm()` は使わない。既存のモーダルとトーストの仕組みを流用する
- スマホ縦画面ファースト、最大幅 480px を維持
- 日数カウントは仕込み当日を 0 日目とする
- UI 文言はすべて日本語
- 変更対象は `index.html` の 1 ファイルのみ。ビルド構成・ファイル構成は変えない

## エラー処理

- 日付計算は既存の `addDays()` / `daysElapsed()` を再利用する
- `d1` / `d2` が 0 の場合、該当予定の日付が仕込み当日または前工程と同日になるが、
  予定としては成立するためそのまま登録する
- 仕込み開始日が未来日の場合、`day` が負になる。お知らせカードの条件はいずれも
  一致しないため何も表示されない（既存の表示ロジックと同じ挙動）
- `localStorage` の保存失敗は既存の `save()` が toast で通知する。変更しない

## 検証方法

本プロジェクトにテストフレームワークは無いため、ブラウザでの手動確認とする。

1. `index.html` をブラウザで開く
2. 仕込み開始日を「今日 − 7日」、塩漬け 7 日で登録 → お知らせカードに
   「今日からスパイス工程です」が出ること
3. 仕込み開始日を「今日 − 14日」、7日 + 7日で登録 → 「今日が完成予定日です」が出ること
4. 仕込み開始日を「今日 − 20日」、7日 + 7日で登録 → 「6日過ぎています」が出ること
5. 通常の仕込み（今日開始）を登録 → お知らせカードが表示されないこと
6. 通知モーダルの2つのリンクの `href` を確認し、日付・時刻・件名が正しいこと
7. リンクを押した後、カードのボタンが「通知は登録済み」に変わること
8. 開発者ツールのスマホ表示（幅 412px）でレイアウトが崩れないこと
