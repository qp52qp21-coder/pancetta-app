# 熟成条件の編集と、写真つき日誌 — 設計

作成日: 2026-09-06

## 背景と目的

仕込み後に直せるものが何も無かった。熟成日数を打ち間違えても、開始日を間違えても、
記録できるのは重量だけで、途中で気づいたことを書き残す場所が無い。

この設計で次の3つを足す。

1. 仕込み内容の編集（熟成日数・開始日を含む）
2. 日付つきの日誌（メモ）
3. 日誌への写真添付

## 決めたこと（採用案と、採らなかった案）

| 論点 | 採用 | 採らなかった案とその理由 |
|---|---|---|
| メモの形 | 日付つきの追記式 | 1枚の自由メモ。工程が日ごとに進むので「いつ何をしたか」が残らないと次回の改善に使えない |
| 編集できる範囲 | 全8項目 | 日数だけ／日程まわりだけ。%の打ち間違いを訂正できないのは不便との判断 |
| 写真の保存先 | IndexedDB | localStorage。上限5MBで30枚ほどで満杯になり、あふれた後は重量記録の保存まで巻き添えで失敗する |
| 重量と日誌の関係 | 1つの「記録する」に統合 | 別々のボタン。カードのボタンが6つになり、押し分けの判断が毎回発生する |
| 日程変更時の通知 | 登録済みフラグを自動で解除 | 確認モーダルを挟む（手間が増える）／何もしない（ズレた通知に気づけない） |

## データ構造

`weights` を廃止し `logs` にする。

```js
batch = {
  id,          // 文字列（Date.now().toString(36)）
  name,        // 仕込み名
  startDate,   // "YYYY-MM-DD" 仕込み開始日
  d1,          // 塩漬け日数
  d2,          // スパイス熟成日数
  saltPct,     // 塩の割合(%)
  sugarPct,    // 砂糖の割合(%)
  meatWeight,  // 仕込み時の肉重量(g)
  spice,       // スパイスメモ（文字列）
  logs,        // 記録の履歴（後述）
  status,      // 'curing' | 'done'
  rating,      // 1〜5（完成時の★評価）
  memo,        // 味のメモ（完成時。logs とは別物）
  doneDate,    // 完成日 "YYYY-MM-DD"
  calReg       // カレンダーへ通知を登録したか
}

log = {
  id,          // 文字列。記録1件の識別子（削除に使う）
  date,        // "YYYY-MM-DD"
  grams,       // 数値 または null（重量を書かなかった日）
  memo,        // 文字列（空文字可）
  photos       // 写真IDの配列（0〜4件）。画像の実体は入れない
}
```

`logs` は**日付の昇順**で保持する。新しい記録は日付順の正しい位置に挿入する
（同じ日付が複数あってよい。同日内は追加順）。

`log.id` と写真IDは `Date.now().toString(36)` に乱数4桁を足した文字列で作る
（同じミリ秒に複数の写真を保存してもぶつからないようにするため）。

### 写真の保存先

画像の実体は IndexedDB に置く。

- DB名 `pancetta-photos` / ストア名 `photos` / キー `id`
- レコード `{ id, batchId, blob, created }`
- `batchId` にインデックスを張る（仕込み削除時にまとめて消すため）
- 値は Blob のまま保存する（文字列化すると約1.3倍にふくらむため）

localStorage に入るのは今までどおり `batch` の配列だけで、写真IDの文字列しか増えない。

### 既存データの移し替え

`load()` の中で、`weights` を持つ batch を見つけたら変換する。

```
logs = weights.map(w => ({ id:新規, date:w.date, grams:w.grams, memo:'', photos:[] }))
weights は delete する
```

- 変換したら即 `save()` する（次回以降は走らない）
- `logs` も `weights` も無い古いデータは `logs: []` を与える
- 一度きり・自動・操作不要。既存の重量記録は失われない

## 画面

### 熟成中カードのボタン

```
[ 記録する ] [ 完成にする ]
[ 編集 ]     [ 削除 ]
[ 🔔 通知をカレンダーに登録 ]
```

「重量を記録」を「記録する」に置き換え、「編集」を追加する。

### 記録モーダル（新規・重量記録モーダルを置き換え）

見出し「今日の記録」。サブに `仕込み名 ・ N日目`。

入力欄:

| 欄 | 必須 | 備考 |
|---|---|---|
| 日付 | ○ | 既定は今日。過去日・未来日とも制限しない |
| 重量（g） | 任意 | 空なら `grams: null` |
| メモ | 任意 | 複数行 |
| 写真 | 任意 | 最大4枚 |

- 重量・メモ・写真がすべて空のまま「記録する」を押したら、
  トースト「重量・メモ・写真のどれかを入力してください」を出して保存しない
- 重量に0以下や数値でない値が入っていたら、トースト「重量は正の数で入力してください」を出して保存しない

履歴（モーダル下部、新しい順に表示）:

- 日付 / 重量と初回比の減少率 / メモ / 写真サムネイル / 削除ボタン「✕」
- 重量が `null` の行には重量と減少率を出さない
- 減少率の基準は **`grams` を持つ記録のうち最も古いもの**

### 編集モーダル（新規）

見出し「仕込みを編集」。次の8項目を直せる。

仕込み名 / 仕込み開始日 / 塩漬け（日）/ スパイス熟成（日）/ スパイスメモ /
塩（%）/ 砂糖（%）/ 仕込み重量（g）

入力の検証:

- 仕込み名が空なら「パンチェッタ」を入れる（新規登録と同じ扱い）
- 開始日が空なら保存しない（トースト「仕込み開始日を入力してください」）
- 日数は1以上の整数。満たさなければ保存しない（トースト「日数は1日以上で入力してください」）
- 塩%・砂糖%・仕込み重量は0以上。負の数は保存しない

**仕込み重量と重量記録の整合**:

仕込み重量の欄の下に、次の注記を常時表示する。

> ※ 重量記録の1件目（460g・基準）も同じ値に直します

開始日を変えても、既にある記録の日付はそのまま残す（記録は実際にその日に測った事実のため）。
結果として開始日より前の日付の記録が残ることがあるが、削除も警告もしない。

実際に `logs` を書き換えるのは、1件目が**開始日と同じ日付**で、かつ
**編集前の `meatWeight` と同じ `grams`** を持つときだけ（＝アプリが自動で作った基準値のとき）。
手で書き換えられた記録には触れない。この条件を満たさないときは注記も出さない。

### アーカイブの表示

完成した仕込みのカードに、日誌を折りたたみで載せる。

- 「記録を見る（N件）」を押すと開く。既定は閉じた状態
- 中身は記録モーダルの履歴と同じ体裁（削除ボタンは出さない）
- 写真はサムネイル。タップで全画面表示

## 写真の扱い

### 追加

1. 「＋ 追加」で端末の写真選択を開く（`<input type="file" accept="image/*">`、複数選択可）
2. 選ばれた画像を canvas で**長辺1000px・JPEG品質75%**に縮小する
   （縮小前が1000px以下なら拡大はしない）
3. IndexedDB に `{ id, batchId, blob, created }` として保存
4. 返ってきたIDを `log.photos` に足す

1件の記録につき **4枚まで**。5枚目を選んだらトースト「写真は1件につき4枚までです」を出し、
4枚目までを保存する。

### 表示

- サムネイルは `URL.createObjectURL(blob)` で表示し、描画のたびに前のURLを `revokeObjectURL` する
- タップで全画面表示。全画面には「この写真を削除」ボタンを置く

### 削除

| 操作 | 消えるもの |
|---|---|
| 全画面の「この写真を削除」 | その写真1枚（IndexedDBのレコードと `log.photos` の該当ID） |
| 履歴の行の「✕」 | その記録1件と、その記録が持つ写真すべて |
| 仕込みの「削除」 | 仕込みと、その仕込みの写真すべて（`batchId` インデックスで一括） |

記録1件の削除と仕込みの削除は、既存の削除モーダルと同じ体裁の確認を挟む。
写真1枚の削除は全画面表示からの操作なので確認を挟まない（誤タップしにくい位置のため）。

### 失敗したとき

写真の保存に失敗しても、重量とメモは保存する。
トースト「写真を保存できませんでした」を出す。
IndexedDB が使えない環境では写真欄を出さない（重量とメモは今までどおり動く）。

## カレンダー通知との連動

編集の保存時、**開始日・塩漬け日数・スパイス熟成日数のいずれかが変わり**、
かつ `calReg` が `true` だった場合のみ:

1. `calReg` を `false` に戻す（ボタンが「🔔 通知をカレンダーに登録」の見た目に戻る）
2. トースト「日程が変わりました。カレンダーの予定を登録し直してください」

アプリからGoogleカレンダーの予定を書き換えたり消したりはできないため、
カレンダーモーダルに次の一文を常設する。

> ※ 前に登録した予定は、カレンダーアプリで手で削除してください

## 設計ルールの遵守

- 配色は既存の3色（生成り `#FAF5EE` / 濃茶 `#3B2A22` / ローズ `#B14A5A`）と
  補助色（`#F1E8DC` / `#E7CBCF`）のみ。写真の全画面表示の背景は濃茶の半透明
- `alert()` `confirm()` は使わない。確認はモーダル、通知はトースト
- 単一の `index.html` に内包する。ビルドなし、通信なし
- 追加するアイコン・記号は既存の絵文字ボタン（🥓 ＋ 📖 🔔）の流儀に合わせる

## 実装しないこと

- 写真の並べ替え、トリミング、回転補正
- 写真つきJSONバックアップ（別途の改修として残す）
- 3段階以上の熟成工程
- 完成後の仕込みの編集（アーカイブは読み取り専用のまま）

## 影響範囲

`index.html` のみ。加えて `CLAUDE.md` のデータ構造と機能一覧を更新する。
