# 写真の全画面表示を横スワイプで送れるようにする

2026-09-15

## 背景

全画面表示はサムネイルを押した1枚しか映せず、次を見るにはいちど閉じて
別のサムネイルを押し直す必要があった。仕込みから完成までの見た目の変化は
この日誌の主な中身なのに、並べて追えない。

## 決めたこと

全画面表示を「その仕込みの写真を日付順に並べたアルバム」にして、
横スワイプと左右の矢印ボタンで送れるようにする。

送る範囲は**記録1件の中（最大4枚）ではなく、その仕込みの全写真**。
仕込みから完成までをパラパラと追えることが、この機能の目的のため。

## 実現方法

指の横移動（`touchstart` と `touchend` の差）で判定し、表示中の1枚だけを
IndexedDB から読み直す。

CSS の `scroll-snap` で全枚数を横に並べる方法も検討したが採らなかった。
指の追従は一番なめらかになる一方、その仕込みの写真を全部いっぺんに読み込むため、
枚数ぶんの一時URLを同時に抱えることになる。写真は長辺1000pxで保存しており、
枚数が増えるほど重くなる。

スワイプが空振りしたときの逃げ道として、画面の左右に矢印ボタンも置く。

## 仕様

- **端では止める。** 最後の写真で左に払っても先頭へは戻らない。
  一周すると同じ写真に戻ったことに気づけないため。端の矢印は隠す
- **枚数と日付を出す。** 画像の下に `8/10 ・ 3 / 5` の形。
  アルバムとして送ると今どの日の写真かがわからなくなるため
- **縦向きの動きでは送らない。** 横移動が40px未満、または縦の移動量のほうが
  大きいときは無視する（画面を送るつもりのことがある）
- **削除したら次の写真へ進む。** 見ながら間引く使い方になるため。
  最後の1枚を消したときだけ閉じる。アーカイブから開いたときは今まで通り
  削除ボタンを出さない
- **下書き（まだ保存していない写真）も束ねる。** その場合は日付を出さない

## 一時URLの扱い

一度表示した写真の `URL.createObjectURL` はアルバムを閉じるまで `albumUrls`
（Map）に残し、行き来しても読み直さずに済ませる。閉じるときにまとめて破棄する。

**`objUrls` とは別に持つ。** `render()` が `freeUrls()` で `objUrls` を破棄するため、
混ぜると削除のたびに表示中の写真まで道連れになる。

読み込み中にさらに送られた場合は、届いた画像が今の1枚と一致するか確かめてから貼る。
