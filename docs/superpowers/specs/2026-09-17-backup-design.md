# 記録と写真の書き出し・読み込み

2026-09-17

## 目的

1. **Cloudflare 版への引っ越し**：同じスマホの中で、GitHub Pages の URL から Cloudflare Pages の URL へ記録を移す
2. **万一に備えた控え**：ブラウザのデータ削除などで記録が消えたときに戻す

記録（localStorage）と写真（IndexedDB）は URL（オリジン）ごとに別々に保管されるので、
URL が変わると記録は1件も見えない。今は移す手段が無い。

## 決めたこと

- **1つのファイル（`.json`）に記録と写真をまとめる**。写真は文字（base64）にして入れる。
  ZIP は小さくなるが部品を外から読む必要があり、「ファイル1つで動く」作りから外れるので採らない
- **書き出しは「ファイルに保存」だけ**。スマホの「ダウンロード」に保存する
- **読み込みは足し合わせ**。決まりは1つだけ：
  **手元に無い仕込みは写真ごと追加する。手元にある仕込みには触らない。**
  古い控えをうっかり読み込んでも、今の記録は上書きされない
- 読み込む前に中身を見せて確認する（追加する仕込みの件数と名前・写真の枚数・変えない仕込みの件数）

### 採らなかったもの

- **子どもとの記録の共有**：同じ仕込みへの記録の足し込み、完成状態の優先、
  消した記録が読み込みで戻る問題、カレンダー登録済みの扱いなど、込み入った部分がすべて共有のためだった。
  引っ越しと控えでは読み込み先に同じ仕込みが無いので不要。
  あとで要るようになったら、ファイルの形は変えずに足し込みの決まりだけ追加できる
- **「送る」ボタン**（LINE・Googleドライブなどへの共有）：共有をやめたので不要。
  スマホを失くしたときの控えにするなら、保存したファイルを手で Google ドライブに上げる

## ファイルの形（version 1）

```json
{
  "format": "pancetta-techo-backup",
  "version": 1,
  "exportedAt": "2026-09-17T03:12:45.000Z",
  "batches": [ /* localStorage の pancetta-batches と同じ形 */ ],
  "photos": [
    { "id": "…", "batchId": "…", "created": 1789000000000, "type": "image/jpeg", "data": "<base64>" }
  ]
}
```

- `format` が違うファイルは取り込まない
- `version` が 1 より大きいファイルは「新しい版のアプリで書き出したファイル」として取り込まない
- 写真は、仕込みの記録から参照されているものだけを入れる（どこからも使われていない画像は入れない）

## 画面

アーカイブ画面のいちばん下に「記録の書き出し・読み込み」のカードを置く。タブは増やさない。

- 説明文、「前回の書き出し：2026/9/17」、ボタン2つ（ファイルに保存 / 読み込む）
- 前回の書き出し日は端末ごとに `localStorage` の `pancetta-last-export` に持つ
- 読み込みの確認はアプリ内の小窓で行う（`confirm()` は使わない）

## 失敗したとき

| 場面 | 動き |
|---|---|
| 手帳のファイルではない / 壊れている | 取り込まずにトーストで知らせる |
| 追加する仕込みが1件も無い | 小窓を出さず「すべて取り込み済み」と知らせる |
| 写真の保存箱が使えない端末 | 記録だけ取り込み、写真は取り込めなかったと知らせる |
| 一部の写真が保存できない | 記録は取り込み、失敗した枚数を知らせる |
| 書き出し時に写真が見つからない | その写真を除いて書き出し、枚数を知らせる |

写真を先に保存し、そのあと記録を保存する。記録だけ先に入ると、写真の無い記録が一瞬できるため。

カレンダー通知の「登録済み」はファイルの状態をそのまま引き継ぐ（引っ越しも控えも、予定はすでにカレンダーにある）。
